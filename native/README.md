# MyGo 数据提取

MyGo 原生 Go 界面使用 Onevra（`github.com/oneo-me/onevra/source v0.2026.18`）组件与图表库，直接调用 Rust 提取引擎。没有 HTML、JavaScript 界面、Electron 或 HTTP 服务。

## 运行

在仓库根目录运行：

```sh
npm run bootstrap
npm start
```

需要 Node.js、Cargo 和 Go 1.27.4+。macOS arm64 缺少 Go 时，启动脚本会校验并解压项目内的 Go 工具链到 `.tmp/toolchains/`，不修改系统安装。其他平台先安装 Go，或设置 `DATA_COS_GO`。

```sh
npm run build:mygo
npm run test:mygo
npm run test:mygo:e2e
```

`build:mygo` 使用 MyGo CLI 打包本机平台，将 Rust 提取引擎放入平台资源中。macOS 输出位于 `native/build/darwin-arm64/`。构建不执行发布或上传。

`test:mygo` 构建 Rust 提取引擎，运行 Go 竞争检测、真实 Excel 文件提取、原生界面交互及 `go vet`。原生界面检查覆盖 1440×900 和 1000×720。旧版 Electron 仍可以使用 `npm run start:electron`。

`test:mygo:e2e` 使用仅测试构建导入的 MyGo 自动化插件运行真实原生窗口，结束时关闭本次窗口和进程。截图与记录默认写入 `output/playwright/uix-refactor/`；`DATA_COS_UI_OUTPUT` 可以指定本次检查的输出目录。

## 使用

1. 选择模块或芯片模式。
2. 设置数据根目录，或直接输入完整路径。
3. 每行输入一个编号，选择测试文件和测试站别。
4. 输入电流点，点击「开始提取」。
5. 在结果表中搜索、排序、调整列宽或横向滚动，或切换到「数据图表」查看折线／面积／柱状图与多指标对比。
6. 用「导出结果」导出 Excel 或 CSV。

左侧按编号、电流点、测试站别、提取按钮的顺序排列。编号输入框保持紧凑高度，长清单在框内滚动；测试站别列表占据剩余高度，内容超出时独立滚动；提取按钮固定在左侧底部。右侧结果表占满可用高度。左栏默认宽度为 304 DIP，中间分隔条支持拖动调整宽度。数据根目录与测试文件类型收在右上角设置中。

电流提供「最大值」「全部」「指定」三段切换；仅在「指定」时显示输入框，支持 `2, 4, 8~12`。整数范围逐点展开；小数范围保留两端，与旧版规则相同。无效电流保留输入框的校验标记，并禁用提取；具体错误统一显示在「查找提示」中。站别采用整行点击区域；自定义站别只有点击「保存站别」才写入配置，取消和 Escape 丢弃草稿。

站别标题右侧的加号按钮打开自定义站别清单，悬停与无障碍名称为「自定义测试站别」。保存后，名称直接加入主界面的站别列表，默认勾选。新增站别与常用站别共用同一复选框，支持鼠标、空格键、全选和清空；只提取勾选的站别。自定义站别的勾选状态随配置保存。站别较多时列表独立滚动，长名称用省略号显示。

勾选站别后，点击加号按钮右侧的删除图标，一次删除全部勾选的站别。没有勾选或提取期间，删除按钮禁用。图标按钮提供中文悬停提示与无障碍名称；站别不提供右键菜单。删除只移除站别配置，不删除测试文件或已有提取结果。删除状态随配置保存；全选不会恢复删除的站别，可以通过加号按钮重新添加。

「整理编号清单」移除空行和重复编号，保留原始顺序。结果表默认按编号、站别、电流分组，以编号分隔线与站别浅底色区分数据；按数值排序时恢复每行的编号与站别。结果表支持按住 Ctrl／Command 多选、Shift 连选、按数值排序以及右键复制单元格。复制图标的悬停名称会说明当前复制的是选中记录还是筛选后的记录。

快捷键：Ctrl／Command + Enter 提取；+ L 聚焦编号；+ F 聚焦结果搜索；表格内 + C 复制选中记录；表格内 Escape 清除选择。

模块编号的路径规则保持不变：编号按字符拆成多级目录。包含路径分隔符的输入直接视为路径。芯片模式保留 `postQCW` 和年月目录查找规则。

导出包含本次全部记录，搜索只影响界面和复制。Excel 使用数值单元格保存引擎返回的数值，附带「提取提示」工作表。Excel 与 CSV 导出不额外舍入。界面中的数值最多保留三位小数（省略末尾多余零）。

配置与旧版隔离，保存在系统配置目录下的 `data-cos-suite-mygo/settings.json`。结果只保存在内存中。`DATA_COS_SETTINGS_PATH` 可以覆盖配置路径；`DATA_COS_EXTRACT_BIN` 可以指定提取引擎。

## 架构

- `view.go`：Onevra 输入框、复选框、按钮、分栏、分段标签页、虚拟表格、模态对话框与系统文件对话框。
- `chart_view.go`：Onevra `components/chart` 数据图表视图（折线、面积、柱状图、多指标与按电流曲线／按编号对比、表格选中序列聚焦）。
- `controls.go`：简约单色浅／深主题配置、常用控件封装及复制反馈。
- `icons.go`：基于 Onevra `lucide` 图标与 `IconButton` 的工具按钮。
- `app.go`：任务快照、取消、结果与图表状态、搜索和排序。
- `model.go`：输入校验、电流解析与配置保存。
- `engine.go`：子进程生命周期及 JSON 协议。
- `export.go`：复用 Excelize 导出 Excel；标准库导出 CSV。
- `../rust/crates/data-cos-data-adapter/src/bin/data-cos-extract.rs`：只接收一次提取请求的 Rust 程序。

MyGo 固定到 `614ea7a6af6e` 对应的模块版本，UI 与图表组件基于 `github.com/oneo-me/onevra/source v0.2026.18`。自动化插件只在 `e2e` 构建标签下导入，不进入普通构建。原有 Rust 数据规则和旧版前端保持独立。

UI 设计使用 unslop by Damir Sokolovsky（[@heydamir](https://x.com/heydamir)）的检查方法，遵循 CC BY 4.0 署名要求；图标沿用 Lucide（ISC）。

结果使用下划线页签。读取错误、操作错误与输入校验说明统一显示在「查找提示」中，页签显示错误和查找提示的总数。部分成功时保留结果表，底栏只显示记录数；没有记录时自动打开「查找提示」。清空结果会清除本次结果与操作错误；校验提示随输入更新。


## 图表工作区

折线图与箱线图沿用确认后的布局：上排选择指标、基准与图表类型，下排选择维度、对比电流、范围与排序。原有面积、柱状、基准差值、全量均值、放大差异、极值代表序列和编号窗口功能保留。

统计摘要分开显示标签、数值和样本上下文；长上下文通过悬停查看。图例统一放在右侧，单击切换显隐，双击独显，再次双击恢复，隐藏后可使用「全部显示」。右侧列表在序列较多时独立滚动。折线图图例中的数值对应标题注明的末端电流；该电流缺少数值的序列显示「—」，不以别的电流值代替。

箱线图按当前维度与对比电流显示各组中位数、Q1、Q3、样本数及统计异常点数。局部纵轴范围直接标在图下。少量异常点标注编号和值；异常点较多时保留全部圆点，按当前聚焦组显示少量文字，其余编号与统计值通过原有悬停提示查看。窄窗口的箱线说明收为悬停说明，统计区保留独立滚动。

图表计算继续使用原有记录、分组、四分位数、1.5 倍四分位距和降采样逻辑。绘制层不改写记录或缓存载荷，显示格式仍最多三位小数，复制和导出的精度规则不变。
